# rbx place

Upload, download, promote and roll back place files, across the envs of `rbxplace.toml`.

```sh
rbx place upload --env staging --file build.rbxl
rbx place upload --env prod --file build.rbxl --published   # prompts if prod has confirm = true
rbx place promote --from staging --to prod
rbx place rollback --env prod
```

An env with `confirm = true` asks before every write, once per run. A place locked by Team Create fails at once with a clear message. The module game code imports is generated by [`rbx env codegen`](env.md#rbx-env-codegen).

## Commands

### rbx place upload

Upload a `.rbxl` to one place, every place of an env, or every env. Saved as a draft unless `--published`.

```sh
rbx place upload --env staging --file build.rbxl
rbx place upload --env prod --place lobby --file build.rbxl --published
rbx place upload --env prod --all-places --file build.rbxl
rbx place upload --env all --file build.rbxl --yes
```

| Flag | Description |
| --- | --- |
| `--file` | The `.rbxl` to upload (required) |
| `--all-places` | Every place of the env, instead of `--place` |
| `--published` | Publish live instead of saving a draft |
| `--yes` | Skip the confirmation |
| `--json` | One JSON receipt on stdout. See [Write documents](#write-documents) |

`--env` takes `all` or a group name here. Then:

- Every target is resolved before the first upload, so a `--place` missing from one env fails the whole run up front.
- One confirmation covers every env, and names them.
- Envs are written in order (`all` alphabetically, a group as declared). The run stops at the first failure: earlier envs keep their new version, later ones are not touched.

!!! warning "150 MiB at most"
    A file over 157,286,400 bytes is refused before anything is sent. Roblox would answer `400 Request upload was interrupted before completion`, which reads like a network error, and a retry fails the same way. Measured on 2026-11-09: the spec documents no limit. `promote` applies the same limit to the source version.

### rbx place download

```sh
rbx place download --env prod
rbx place download --env prod --version 42 --out backup.rbxl
rbx place download --place-id 123456789012345 --out backup.rbxl
```

| Flag | Description |
| --- | --- |
| `--version` | A specific version (default: latest) |
| `--published` | The latest published version |
| `--saved` | The latest saved draft |
| `--out` | Output path (default `<place_id>.rbxl`) |

One env only.

### rbx place promote

Copy a place from one env to another: download the source in memory, upload it to the target. The place goes to the place of the same name in the target env.

```sh
rbx place promote --from staging --to prod
rbx place promote --from staging --to prod --from-published --published
rbx place promote --from dev --to staging --version 42
rbx place promote --from staging --to prod --log deploy.json
```

| Flag | Description |
| --- | --- |
| `--from` / `--to` | Source and target env (required). `--env` is refused here |
| `--version` | A specific source version |
| `--from-published` / `--from-saved` | The source's latest published version, or latest draft |
| `--published` | Publish live on the target |
| `--all-places` | Send the source place to **every** place of the target env |
| `--log` | Record the promotion in a JSON file, merged with what it holds |
| `--yes` | Skip the confirmation |
| `--json` | One JSON receipt on stdout |

!!! warning "`--all-places` copies one place over all of them"
    Every place in the target env receives the same file, from the one source place. `lobby` does not go to `lobby`. Undoing it is one rollback per place. To promote each place to its counterpart, run promote once per place.

`--log` writes, per place:

```json
{
  "main": {
    "deployedAt": "2026-05-14T15:30:00+01:00",
    "staging": { "universeId": 9876543210, "placeId": 123456789012345, "version": 172 },
    "production": { "universeId": 9876543211, "placeId": 234567890123456, "version": 27 }
  }
}
```

### rbx place rollback

Make a past version current again. Roblox creates a new version from it, published. Without `--version`, a picker lists recent versions.

```sh
rbx place rollback --env prod
rbx place rollback --env prod --version 42
```

| Flag | Description |
| --- | --- |
| `--version` | The version to restore. Required with `--json` |
| `--count` | Versions shown in the picker (default `10`) |
| `--yes` | Skip the confirmation |
| `--json` | One JSON receipt on stdout |

### rbx place versions

```sh
rbx place versions --env prod
rbx place versions --env prod --filter published --count 5
```

| Flag | Description |
| --- | --- |
| `--count` | How many (default `20`, or `3` with a filter) |
| `--filter` | `all` (default), `published` or `saved` |
| `--json` | One JSON document on stdout |

#### `--json`

```json
{
  "schema_version": 1,
  "env": "prod",
  "place": "main",
  "place_id": "123456789012345",
  "filter": "all",
  "count": 20,
  "count_reached": false,
  "versions": [
    { "version": "173", "published": true, "create_time": "2024-01-15T14:30:00Z" }
  ]
}
```

| Field | Type | Meaning |
| --- | --- | --- |
| `env` | string | Absent with `--place-id` |
| `place` | string | The place name, or the id with `--place-id` |
| `place_id` | string | |
| `filter`, `count` | string, integer | As requested |
| `count_reached` | boolean | `true` if there may be more: raise `--count` |
| `versions[]` | array | Newest first: `version` (string), `published` (bool), `create_time` (RFC 3339) |

### rbx place places

List every place of a universe, and which ones `rbxplace.toml` maps.

```sh
rbx place places --env prod
rbx place places --universe-id 9876543210
```

| Flag | Description |
| --- | --- |
| `--json` | One JSON document on stdout |

#### `--json`

```json
{
  "schema_version": 1,
  "env": "prod",
  "universe_id": "9876543210",
  "places": [
    { "place_id": "123456789012345", "display_name": "Main Place", "max_player_count": 50, "place": "main", "configured": true },
    { "place_id": "987654321", "display_name": "Test Arena", "configured": false }
  ]
}
```

`env` is absent with `--universe-id`. Per place: `place` is the `rbxplace.toml` key (absent if unmapped), `configured` says whether the file maps it (absent without an env), `max_player_count` is absent if Roblox gives none.

### rbx place fetch

Fill an env's places in `rbxplace.toml` from the live universe. Existing keys are kept; new places get a key from their display name.

```sh
rbx place fetch --env prod            # show what would be written
rbx place fetch --env prod --write
```

| Flag | Description |
| --- | --- |
| `--write` | Write the file (default: show only) |

## Write documents

`upload`, `promote` and `rollback` print the same receipt with `--json`.

```json
{
  "schema_version": 1,
  "command": "upload",
  "ok": true,
  "env": "staging",
  "universe_id": "9876543211",
  "published": false,
  "place_id": "234567890123456",
  "version": "173",
  "created": true,
  "results": [
    { "place": "main", "place_id": "234567890123456", "version": "173", "created": true }
  ]
}
```

| Field | Type | Meaning |
| --- | --- | --- |
| `command` | string | `upload`, `promote` or `rollback` |
| `ok` | boolean | `false` if a target failed (the exit code is non-zero too) |
| `env` | string | The env written to (the target, for `promote`) |
| `from_env` | string | `promote` only |
| `universe_id` | string | |
| `published` | boolean | Always `true` for `rollback` |
| `source_place`, `source_place_id` | string | `promote` only |
| `source_version` | string | The version promoted or restored. Absent for `upload` |
| `place_id`, `version` | string | Single-target runs only. Absent with `--all-places` |
| `created` | boolean | `false` when the place already held this exact file and Roblox made no new version. Absent if the key cannot list versions, and for `rollback` |
| `results[]` | array | One `{ place, place_id, version, created }` per place written, in order |
| `error` | string | Why the run stopped. Absent when `ok` |

- **`created: false` means nothing changed.** Usually a stale `--file` or a build step that failed quietly. The human output says `(unchanged)`.
- **A run that fails partway still prints a receipt**, listing the writes that happened. A failure before any write prints nothing on stdout.
- **The shape follows the command line**: `--all-places` never fills `place_id` and `version`, even for an env with one place.
- **No prompt under `--json`**: a needed confirmation fails instead, naming `--yes` (or `--version` for rollback).

With `--env all` or a group, `upload` wraps one receipt per env, in write order:

```json
{
  "schema_version": 1,
  "command": "upload",
  "ok": true,
  "results": [
    { "command": "upload", "ok": true, "env": "dev", "version": "41" },
    { "command": "upload", "ok": true, "env": "staging", "version": "174" }
  ]
}
```

```sh
VERSION=$(rbx place upload --env staging --file build.rbxl --yes --json | jq -r .version)
```

## Without `rbxplace.toml`

`--place-id` works for the reads (`download`, `versions`). The writes refuse it: `confirm` lives on an env, and the receipt reports one.

## Required API scopes

| Operation | Scope |
| --- | --- |
| Upload, promote (write) | `universe-places:write` |
| Download, promote (read) | `legacy-asset:manage` |
| Versions, `--from-published`, `--from-saved`, `--published`, `--saved` | `asset:read` |
| Rollback | `asset:write` |
| `places` | `universe:read` |
